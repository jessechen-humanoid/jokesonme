## Context

平台是 Next.js（App Router）＋ Supabase，樣式集中在 `platform/app/globals.css`，沒有 CSS 框架。現行版面：每頁一張柿子紅標題卡、白色大圓角區塊、底部導覽（電腦變左側欄）、浮動＋按鈕。

## Goals / Non-Goals

**Goals:** 每頁一眼看懂主角是什麼、常用動作少一步、手機與電腦都順。
**Non-Goals:** 不動資料結構與伺服器動作參數；不加 UI 套件。

## Decisions

### 精簡頂列取代標題卡

頂列 = 頁名（24px）＋右側頭像，子頁左側加「‹ 上一層」。分段按鈕用中性灰底白色選中，不再用柿子紅底。柿子紅只留給「下一場」大卡、主要按鈕、＋按鈕、目前分頁、急件日期。理由：標題卡在手機佔 1/4 螢幕且每頁都一樣，沒有資訊量。

### 筆記就是靈感

LINE 的 `/筆記`、`/note` 本來就存進靈感表，Jesse 也叫它筆記。畫面一律叫「筆記」，資料表與路徑 `/ideas` 不改。

### 頁面上直接輸入

演出頁與筆記頁頂端放一個輸入框，按「存」直接建立，不開面板。筆記頁的輸入框可先點一個演出標籤（預設不掛演出）。沿用既有 `createIdea` 動作。

### 歸位改成安靜的標籤

卡片右下一個演出標籤（沒掛就顯示灰字「選演出」），點了開共用選演出面板。編輯面板也能換演出：存檔時文字有變呼叫 `updateIdea`，演出有變呼叫 `assignIdea`。

### 待辦收合卡

演出頁的待辦預設是一張摘要卡（未完成 N 件、最近截止日）；點開後顯示既有的 `TodoBoard`。電腦版因為有右欄空間，預設展開。

### 截止日急迫度

新增純函式 `dueUrgency(dueDate, today, done)` 回傳 `overdue | soon | later | none`，放在 `lib/todos.ts` 方便測試。

### 資訊保留清單

改版前各頁顯示、改版後必須仍看得到的資訊（拿掉的只有演出文件）：

| 頁面 | 資訊 |
| --- | --- |
| 待辦 | 我的／全部／未認領件數、下一場（名稱、日期、倒數）、各演出群組名稱與日期與件數、待辦標題、截止日、負責人或未認領、來源（LINE／模板／手動）、完成者、已完成切換 |
| 筆記 | 內容、作者、時間、LINE 來源、演出名稱、各分頁件數、已封存與還原 |
| 演出列表 | 下一場（倒數、日期、類型、未完成待辦數）、之後各場（日期、未完成件數）、已演出／其他（含已歸檔） |
| 演出頁 | 名稱、類型、日期、已歸檔、待辦全清單、筆記、編輯演出資訊 |
| 行事曆 | 月曆、演出／行程／待辦三種點、當日清單（時間、標題、類別）、演出資料過期提示、圖例 |
| 收支 | 專案選擇、收入／支出／淨利、每筆的備註、分類、日期、墊款人、結清狀態、分配說明、系統自動、金額、CSV 下載 |
| 逐筆 | 現有全部欄位 |
| 分析 | 年度三數字、共同基金六數字、成員報表五欄、新增結算／代墊還款、收入與支出佔比、各專案損益排序表 |

## Risks / Trade-offs

- 本機預覽連的是正式資料庫 → 驗證時不按送出，寫入動作沿用既有 server action，不改參數。
- 規格依賴：`visual-consistency` 尚未 archive，本 change 的字級規則修改它新增的需求，須先 archive 它。
